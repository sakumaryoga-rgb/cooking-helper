# レシピの取り込みに対応するサイト(確認記録)

取り込みは、各サイトのレシピページの JSON-LD(schema.org/Recipe)から、料理名・人数・材料(分量つき)だけを読む。
作り方・画像・説明文は取得も保存もしない。元のページへのリンクを必ず残す。
利用者が貼った1ページだけを、ログイン中の利用者の操作でサーバー(api/recipe-import.js)から取得する(巡回はしない)。
取得先は src/lib/recipeImport/sites.js のホストと URL の形だけ(SSRF 対策。ほかのホストへのリダイレクトもたどらない)。

## 対応しない

| サイト | 理由 |
| --- | --- |
| クックパッド | レシピページに JSON-LD・構造化データがない(画面の HTML を解析する必要があるため対応しない) |
| 白ごはん.com | 構造化データ(microdata)に材料がない |
| キユーピー | JSON-LD の材料に分量がない(材料名だけ) |
| ミツカン | レシピページの場所を確認できなかった |

対応しないサイトの URL は、URL を残したまま、料理名と材料を手動で入れて保存できる。

## ロゴ・商標

- 各社の公式ロゴは使わない(利用の許諾がなく、多くの企業はロゴの使用に許可を求めているため)。
- 画面では、サービス名(文字)と、イメージカラーの丸に頭文字を置いた目印で示す。ロゴを模した図形・書体は使わない。
- 「COOKDOOR は各サービスと提携していません。サービス名は各社の商標または登録商標です」と必ず添える。
- 「公式」「提携」「認定」などの言葉は使わない。

## サイトを足すとき

1. robots.txt でレシピページが禁止されていないこと、利用規約で自動取得が禁止されていないことを確認する。
2. 実際のレシピページ数件で、JSON-LD から料理名と材料(分量つき)が読めることを確認する。
3. sites.js に URL の形を足し(id は英小文字だけ)、sites.test.js にそのサイトの書き方を模したテストを足す。
