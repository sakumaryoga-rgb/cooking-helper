# v1.15.0 リリース手順(レシピの削除・作り方の手順入力・食材の整合性・表記揺れ)

DB の変更なし(Migration なし)。既存の RLS(選んでいる家のレシピ・家庭の別名だけ書き込める)のまま動く。
011 と 017 は適用しない。

## 変更

- レシピの削除: 詳細の「編集・削除」→ 編集画面の下の「このレシピを削除」→ 確認ダイアログ。
  材料の行も消える。冷蔵庫の食材と作った記録は残り、作った記録の取り消しもできる(DB テストで確認)。
- 作り方: 番号付きの手順の一覧で入力(手順の追加・並べ替え・削除)。保存の形は従来どおり1手順1行。
- 冷蔵庫とレシピの食材の整合性:
  - 食材を選ぶ画面の「登録済みの食材」をなくし、冷蔵庫にある食材もカテゴリの中に「冷蔵庫に 3個」と出す。
    選ぶと冷蔵庫のその行を使う(同じ食材の行を二重に作らない)。レシピで使っている材料は選べない。
  - 食材マスタに結び付いていない以前の冷蔵庫の行は「その他」に出す。カテゴリに「その他」を追加。
  - レシピから取り込んだ、食材マスタにない食材は、名前からカテゴリを推定して家庭の品目に登録し、冷蔵庫の行と結び付ける
    (以前は冷蔵庫の行だけ作っていたため、冷蔵庫の「食材を選択」のカテゴリに出なかった)。
  - 「リストにない食材を追加」で、表記だけ違う同じ食材(じゃが芋 / じゃがいも)が冷蔵庫にあれば、それを使う。
- 食材名の共通の正規化と名寄せ(lib/ingredientName)。レシピの取り込み・オリジナルレシピ・レシピ編集・冷蔵庫への追加・
  食材の検索・取り込み時の付け替えで同じ処理を使う。表記の違いを吸収するだけで、違う食材はまとめない。
  1. 表記の統一: 全角・半角、空白、かっこ書き、ひらがな・カタカナ
  2. 名前の分解: 大きさ(中・大・小・M・L、「(中)」「中」)、表記上の修飾(新・国産・有機 など)、
     状態の修飾(冷凍・乾燥・干し・加熱済み・ゆで・水煮 など)を本体の名前から分ける。元の表記は残す
  3. 照合: 家庭の別名 → 冷蔵庫の食材 → 食材マスタ → 共通の別名(DB の辞書 + コード側の語の単位の辞書)。
     冷蔵庫にある食材はその行に結び付け、二重に作らない
  4. 数量・単位は材料の行から別に取り出し、名前の処理では変えない。食材の単位と違うときは換算せず、分量を空にして入れてもらう
  - A 自動で確定: 名前が同じ / 別名辞書にある / 大きさ・表記上の修飾を外すと一意に一致し、状態の修飾がない
  - B 候補から選ぶ: 状態の修飾がある / 部分一致・類似 / 候補が複数。選ぶまで保存しない。類似だけで自動でまとめない
  - C 新しい食材: 似た食材がない。家庭の食材マスタに、名前から推定したカテゴリで登録(共通の食材マスタには追加しない)
  - 学習: 候補・ほかの食材を選ぶと、取り込んだ表記をこの家の別名として覚え、次から自動で確定する。
    設定の「覚えた食材の別名」で確認でき、誤って覚えたものは「忘れる」で消せる。別名は家ごとで、ほかの家には見えない

## 食材名寄せの検証(1,000件)

`src/lib/recipeImport/__fixtures__/ingredient_cases.json`(公開レシピの表記64件 + 合成936件。期待結果は参考値)を、
取り込みと同じ流れ(見出しの除外 → 複数の食材の分割 → 照合)に通して採点する回帰テスト `ingredientCases.test.js` を追加。
誤判定0件・自動判定の件数が下がらないことを CI で確かめる。

| 判定 | 件数 |
| --- | --- |
| 自動で正しく判定 | 439 |
| ユーザーの確認(うち、食材は自動で決まり分量だけ確認: 293) | 561 |
| 未対応・誤判定 | 0 |

材料の1行の読み取りも改善: かっこの中だけの分量(しいたけ(2個))、分量の前のかっこ書き(じゃがいも (計250g)2個)、
分量の後ろの注記(豚バラ肉 1枚 冷凍)、入れ子のかっこ、幅(150〜200g は確認)、kg、「各」「それぞれ」と「・、／と」の分割、
見出し(A:、◆合わせだれ、下味、1. など)、在庫に数えないもの(揚げ油・打ち粉・追加の水)。
