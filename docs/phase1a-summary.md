| 版 | 内容 | main のコミット | タグ | 本番デプロイ |

どちらの版も本番DBのスキーマとデータを変更していない(`supabase/` に差分なし)。

## できるようになったこと

- lint、Vitest(52件)、本番と Preview の両ビルド、ローカル PostgreSQL での DB テストを CI で毎回実行する。
- Preview は本番DBに接続しない。接続先と鍵はバンドルに入らない。
- 新しい版を出すと、アプリ内に更新ダイアログが出る。入力中は帯だけを出して入力を妨げない。
- `public/version.json` の `minSupportedVersion` で、旧版の利用を止められる。
- グループ画面にバージョンが出るので、端末がどの版かを家族が確認できる。
- `v0.0.0`・`v1.0.0`・`v1.0.1` のタグと `docs/release-and-rollback.md` で、前の版に戻せる。

## 確認できたこと(Chrome)

- v0.0.0 から v1.0.0、v1.0.0 から v1.0.1 の更新が、本番で「更新する」から完了した。
- v1.0.1 の本番で、タイトル、manifest、favicon、アイコン、OGP、直接アクセス(`/fridge`、`/recipes`、
  `/auth/callback`)、Supabase の認証と REST の応答が正常。

## まだ確認できていないこと

- 家族の iPhone での受け入れ(`docs/pwa-acceptance-iphone.md`)。特に、ログイン状態の維持、
  家族グループのデータ、Safe Area、更新通知。
- 2026-10-08 の確認中、テスト用ブラウザの cookdoor.app でログイン状態が消えていた(保存領域が空)。
  その時点のコードは v1.0.0 で、v1.0.1 の変更とは関係しない。原因は特定できていない
  (Supabase のセッション期限は無期限、リフレッシュトークンの再利用検知は有効、
  監査ログはDB保存なし)。iPhone でログインが維持されるかを優先して確認する。

## 運用で残っていること

- Supabase Auth の SMTP 送信者名が「お料理ヘルパー」のまま。メールの件名と本文は Supabase 標準の英語。
  変更はユーザーの承認後にダッシュボードで行う。
- `supabase/` の SQL コメントに旧名が残っている(DB の履歴なので変えない)。
