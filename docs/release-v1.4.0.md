# v1.4.0 リリース手順(Phase 3: 食材マスタの権限・別名辞書・不足表示)

承認後に行う。Migration 011 とは独立している(011 はまだ適用しない)。

## 変更

- **食材マスタの権限**: 共通の品目(既存のすべて)は、クライアントから追加・変更・削除できない
  (これまでは誰でも削除できた)。家庭で新しく登録する品目は家庭専用になり、その家庭だけが見て、変更・削除できる。
  未ログインは食材マスタと別名を読めない。
- **別名辞書**: 「人参」「玉葱」「生姜」などの表記の違いを食材マスタの1品目にまとめる(共通の別名106件)。
  レシピURLの取り込みで冷蔵庫の食材・マスタの品目に正しく結びつく。材料選択の検索でも別名で見つかる。
- **常備品**: レシピ詳細で材料を「常備品にする」と、在庫の数量に関係なく「ある」とみなす(塩・しょうゆなど)。家庭ごと。
- **不足表示**: レシピ詳細に「あと何 単位」と不足のまとめ、一覧の「あと少し」のレシピに足りない材料と数量を出す。
  数量は小数第2位まで表示(0.25 本が 0.3 本と出ていた)。小数の誤差で不足にしない。
- **判定**: 作れる / あと少し(不足1〜2品)/ 不足が多い / 材料未登録 の4段階。材料のないレシピを「作れます」にしない。

## 本番適用の順序

| 順 | 操作 | 確認 |

| 1 | `supabase/manual/013_precheck.sql` → `supabase/migrations/013_catalog_ownership_aliases_staples.sql`(全文)→ `supabase/manual/013_postcheck.sql` | postcheck がすべて true、件数が precheck と同じ |
| 2 | v1.4.0 をマージして本番デプロイ、`v1.4.0` タグ | 下の動作確認 |

013 のデータ変更: 既存データの値は変えない。追加するのは列(ingredient_catalog.group_id、ingredients.is_staple)、
別名辞書のテーブルと共通の別名の初期データ、ポリシーとインデックス。食材マスタの名前の一意制約を
「共通の中で一意」「家庭の中で一意」の2つに置き換える。

**アプリより先に 013 を適用する**。v1.3.0 のまま 013 を適用すると、v1.3.0 で新しく登録する食材は
(家庭を指定しないため)保存できない。v1.4.0 のデプロイまでの間だけの影響。

## 動作確認(iPhone)

1. 「更新する」でバージョン 1.4.0。冷蔵庫・レシピが普段どおり。
2. 冷蔵庫 → 追加 → 検索で「人参」と打つと「にんじん」が出る。
3. 冷蔵庫 → 追加 → 新しい食材を登録できる。その食材を長押しで削除できる。共通の食材は長押ししても削除の確認が出ない。
4. レシピ詳細で不足の材料に「あと○個」が出る。塩などを「常備品にする」と不足から外れる。

## 切り戻し

アプリは v1.3.0 に Instant Rollback。013 は残してよいが、上の「新しい食材を登録できない」影響があるため、
長く v1.3.0 に戻す場合は承認のうえで次を実行して共通への追加を一時的に戻す。

```sql
create policy "authenticated users can add to ingredient catalog" on ingredient_catalog
  for insert to authenticated with check (true);
```
