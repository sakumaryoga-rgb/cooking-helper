# v1.8.0 リリース手順(Phase 7: 一般公開の準備)

承認後に行う。本番 SQL Editor で実行するのは `supabase/migrations/016_public_launch.sql` だけ。

## 変更

- **利用規約・プライバシーポリシー**(`/terms`、`/privacy`、ログイン前でも読める): 公開前のドラフト。
  運営者名・連絡先・合意管轄・責任の上限・データの保存地域は【未確定】のまま。
  同意画面は `VITE_CONSENT_REQUIRED=true` のときだけ出る(**このリリースでは出さない**)。同意の記録は版と日時。
- **お問い合わせ**(`/contact`、設定から): 種類・本文・任意の返信先。入力チェック、10分3件・1日10件まで、
  同じ本文は1日1回、ボット対策(隠し欄・3秒未満の送信は保存しない)。利用者は送った内容を読めない。
  返信先は90日で削除(pg_cron が有効なら毎日自動、無効なら `select purge_contact_emails();` を手動)。
  通知は未実装(`contact_messages.notified_at` を使って後から追加できる)。外部サービスは使わない。
- **管理画面**(`/admin`、運営者だけ設定にリンクが出る): 日別・月別の利用者/PV/グループ、バージョン別、エラー、
  レシピ取り込みの件数・成功率(このリリースから計測)、お問い合わせの一覧と対応状況。
  運営者かどうかは DB の関数(`admin_dashboard` など)が判断し、運営者以外には何も返さない。
  運営者以外の呼び出しは記録し、1時間に5回を超えると締め出す。管理画面から在庫・レシピは変更できない。
- **取り込みの計測**: レシピ URL 取り込み(Vercel Function)が、結果(サイトと成功/取得失敗/材料なし)を利用者の権限で記録する。
- **旧機能**: 冷蔵庫の＋/−を `adjust_stock` に切り替え、現行アプリから旧 RPC の呼び出しをなくした。
  削除は `docs/legacy-removal.md` の前提が揃ってから(今回は削除しない)。

## 本番適用の順序

1. SQL Editor で `supabase/migrations/016_public_launch.sql` を全文実行(既存データの削除・大量更新はない)。
2. 運営者を登録する(ログイン済みの運営者のメールアドレスで):

```sql
insert into app_admins (user_id, note)
select id, '運営者' from auth.users where email = '<運営者のメールアドレス>'
on conflict (user_id) do nothing;
```

3. PR をマージして本番デプロイ、`v1.8.0` タグ。
