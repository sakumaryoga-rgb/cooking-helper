# v1.14.0 リリース手順(オリジナルレシピ・カスタマイズ・軽量化)

本番 SQL Editor で実行するのは `supabase/migrations/023_recipe_custom.sql` だけ。**023 を適用してから v1.14.0 をデプロイする**。
011 と 017 は適用しない。023 は何度実行しても同じ結果になる。

## 既存データへの影響

なし。recipes に instructions(作り方、4000文字まで)・memo(メモ、1000文字まで)・icon(料理の絵)の列を追加するだけで、
既存の行は空のまま。削除・更新はない。

## 適用からデプロイまでの間

v1.13.0 は新しい列を使わないので、そのまま使える。古いアプリに更新を強制する必要はない。

## 変更

- レシピの追加に「自分で考える」を追加(URL なしで、料理名・材料・人数・作り方・メモ・料理の絵を保存)。
  詳細画面に「わが家のオリジナル」の印、番号付きの作り方、メモを表示。
- 保存したレシピの「編集」(料理名・材料と分量・人数・作り方・メモ・絵)。取り込んだレシピも元のリンクを残したまま変えられる。
  材料の差し替えは update_recipe(security invoker = 呼んだ人の RLS がそのまま効く)が1つのトランザクションで行い、
  同じ家の食材だけを受け付ける。調理の記録は材料の行を参照しないので、編集しても取り消しに影響しない。
- 「代替で作れる」の絵文字を 🪄 に変更。該当なしの表示の絵文字を廃止。
- 軽量化:
  - 選んでいる家のデータ(食材・レシピ・ロット・食材マスタ・代替・別名)を Layout で1回だけ読み、画面間で共有する。
    タブを移っても読み直さず、リアルタイムの購読も張り直さない。
  - 「読み込み中」は最初の1回だけ。リアルタイムの通知による読み直しは裏で行い、続けて届いた通知は 150ms でまとめる
    (以前は「+」を押すたびに一覧が「読み込み中」に切り替わっていた)。
  - めったに開かない画面(参加・レシピの追加と編集・家の管理・規約・お問い合わせ・運営者画面)は開いたときに読み込む。
    ライブラリを別ファイルにし、アプリの更新ではライブラリを読み直さない。起動時のアプリ本体は 745KB → 約 112KB(圧縮前)。

## 切り戻し

アプリは v1.13.0 に Instant Rollback できる。023 は残してよい(v1.13.0 は新しい列と関数を使わない)。
