# v1.11.0 リリース手順(複数の家への参加・招待リンクの修正・ログイン)

本番 SQL Editor で実行するのは `supabase/migrations/021_multi_group.sql` だけ(既存データの削除・大量更新はない)。
**021 を適用してから v1.11.0 をデプロイする**(順序が逆だと、2つ目の家の作成・既存の家を持つ人の招待参加が失敗する)。
011 と 017 は適用しない。

## 不具合の原因

- 招待リンクを開いても招待先に入れず、自分の新しい家ができた:
  1. `group_members.user_id` が一意で、参加の RPC も「すでにグループに所属しています」で止まり、家を持つ人は参加できなかった。
  2. 開いた招待を処理するのは「家がない人」の参加画面だけで、家を持つ人はそのままホームに送られていた。
  3. 招待は端末のブラウザに覚えるが、メールのログインリンクが別のブラウザ(LINE 内のブラウザ → Safari、Safari → ホーム画面のアプリ)で
     開くと失われ、参加画面が「家を作る」で開いた。
- ブラウザや端末を変えるとログインし直しになる: Safari・Chrome・ホーム画面のアプリは保存領域が別のため(仕様)。

## 変更

- 1つのアカウントで複数の家に参加・作成・切り替え(設定 → 家の切り替え)。選んだ家は端末ごとに覚え、次回の起動で復元する。
  家を切り替えると画面を作り直し、前の家のデータを表示しない。ヘッダーに選択中の家の名前。
- 選んでいる家は、すべての DB 呼び出しに `x-cookdoor-group` ヘッダーで送り、DB(`my_group_id()`)が本人の所属を確かめてから使う。
  所属していない家を送っても、どの家としても扱わない。読み取りは所属するすべての家(リアルタイム配信のため)、
  書き込み・RPC(在庫・調理・取り消し・招待・別名・代替)は選んでいる家だけ。
- 招待リンク: ログイン後に自動で招待先に参加し、その家を選ぶ(既存の家は残る)。参加済みならその家に切り替える。
  無効・期限切れ・古い形式は日本語で理由を出し、設定や参加画面に招待リンクを貼って参加し直せる。
- ログイン: メールのリンクに加えて、6桁のコードでも同じ画面のままログインできる(下の設定が必要)。
  自分でサインアウトしていないのにログインが切れた場合は、ログイン画面で知らせる。ブラウザごとにログインが必要なことを明記。
  セッションは supabase-js の既定のまま(端末に保存、アクセストークンの自動更新)。期限の固定や独自 DB への保存はしない。
- メールアドレス: 設定画面の自分のアドレスは一部を伏せて表示。家族の一覧には出さない。アプリ独自のテーブルには保存しない
  (お問い合わせの任意の返信先だけ。90日で削除)。

## 旧版のアプリ

`public/version.json` の `minSupportedVersion` を 1.11.0 にした。v1.10.0 以前のアプリは、所属する家が1つの前提で一覧を読むため、
2つ以上の家に入った人が更新していない古いアプリを開くと、家がない扱いになる。v1.11.0 の公開で古いアプリに更新を強制する。
021 の適用から v1.11.0 のデプロイまでの間は、2つ目の家に入る手段がない(旧版は参加画面を家のない人にしか出さない)ので、
v1.10.0 の在庫・レシピ・調理はそのまま使える(ヘッダーなし = 最初の家)。

## 本番での追加の設定(任意・推奨)

6桁のコードでのログインを使うには、Supabase の Authentication → Emails → Templates → Magic link or OTP の本文に `{{ .Token }}` を加える。

```html
<h2>COOKDOOR にログイン</h2>
<p>下のリンクを開くか、アプリの画面で次のコードを入力してください: <strong>{{ .Token }}</strong></p>
<p><a href="{{ .ConfirmationURL }}">ログインする</a></p>
```

設定しない場合も、これまでどおりリンクでログインできる(コードの入力欄は出るが、メールにコードが書かれていない)。

## 切り戻し

アプリは v1.10.0 に Instant Rollback できる。021 は残してよい(v1.10.0 はヘッダーを送らないので、最初に参加した家を使う)。
ただし 021 の適用後に2つ目の家を作った・参加した人は、v1.10.0 では最初の家しか表示されない。
