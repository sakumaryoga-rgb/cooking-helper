# 分量の換算(v1.22.0)

レシピの分量(「1/2束」「大さじ2」「1合」)を、冷蔵庫の食材の単位(g・ml・本など)に直す仕組み。
処理は `src/lib/unitConversion.js` の `resolveConversion` にまとめ、URL の取り込み・レシピの編集・作れるかの判定・「作った」の確認で同じものを使う。

## 優先の順

| 順 | 根拠 | 確定に使うか | 保存先 |
| --- | --- | --- | --- |
| 1 | 同じ単位 | 使う | - |
| 2 | 計量の定義(g⇔kg、ml⇔大さじ15・小さじ5・カップ200・合180) | 使う | `measurement_units`(migration 026)とアプリの同じ定義 |
| 3 | 家庭で確かめた換算(「作った」で覚えたもの) | 使う | `ingredient_unit_conversions`(migration 024、家ごと) |
| 4 | 全体共通の目安(公開資料) | 使わない(候補として見せるだけ) | `ingredient_catalog_unit_conversions`(migration 026) |
| 5 | どれもない | 換算しない(元の表記のまま) | `recipe_ingredients.amount_text` |

## 安全のための決まり

- 共通の目安は、作れるかの断定と在庫の自動の差し引きに使わない。詳細画面では「目安 約50g(1束 ≈ 100g・味の素パーク)」と表示し、
  「作った」の確認画面では初期値として入れるがチェックは外しておく。確かめて引いた量は、家庭の換算として覚えられる(次から 3 になる)。
- 取り込み・編集の画面では、分量を数にできなかった材料に目安を出し、「目安の量で入れる」を押したときだけ数にする。
- 1束・1袋・1パック・1丁は品目ごとの行だけ。単位だけの共通の換算は持たない。
- 状態(生・ゆで・殻つき・むき身・切り身・水煮・生米など)は `state_key` で区別し、レシピの注記(状態)に合う行を選ぶ。
  食材マスタに同じ状態の品目がない資料の行(炊いたご飯、ゆでめん、ウスターソースなど)は結び付けない。
- 家庭専用の品目には共通の目安を付けない(トリガーで拒否)。家庭の換算は家ごとで、ほかの家には効かない(RLS)。
- 数量は小数第6位までで扱い(`lib/quantity`)、使い切るときは在庫ちょうどを引く(v1.18.0 と同じ)。
- 一般の利用者は目安の表を読むだけで、変更できない。運用者が `supabase/seed/unit_conversions.csv` を直し、
  `node scripts/build-unit-conversion-seed.mjs` で migration に反映する。

網羅状況は [unit-conversion-coverage.md](unit-conversion-coverage.md)。
