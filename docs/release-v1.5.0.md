# v1.5.0 リリース手順(Phase 4: 代替食材と調理時の在庫消費)

承認後に行う。Migration 011 とは独立している(011 はまだ適用しない)。

## 変更

- **代替ルール**: 共通の代替ルール64組(方向あり・換算比率つき。例: キャベツ→白菜 0.6、生クリーム→牛乳 は可だが逆はない)。
  家庭ごとに「この代替を使わない」にでき、グループ画面で戻せる。
- **判定**: 作れる / **代替で作れる** / あと少し / 不足が多い / 材料未登録。まずそのものの在庫を全材料に割り当て、
  足りない分だけ残りの在庫から代替する(同じ在庫を重ねて使わない)。単位は食材マスタの単位で換算し、合わない場合は代替しない。
  常備品の扱い、不足量の表示は v1.4.0 のまま。
- **作った**: 確認画面で、そのもの・代替を行ごとに確かめ、使う/使わない・量を変えられる。代替先の在庫を差し引く。
  在庫より多くは差し引かない。ロットは既存と同じ順(日付なし → 購入日の古い順)で消費する。
- **履歴と取り消し**: 最近作った記録を出し、「取り消す」で差し引いた量とロット(購入日)を戻す。2回目の取り消しは何もしない。
- **二重送信・同時操作**: 確認画面を開くたびに送信IDを作り、同じIDは1回だけ反映する。食材の行をロックして差し引くので、
  複数端末から同時に作っても在庫は負にならない(DB テストで同時9本・同時取り消しを確認)。
- 旧 `cook_recipe` は旧版のアプリのために残す(新しい版は `cook_recipe_v2` を使う)。

## 動作確認(iPhone)

1. 「更新する」でバージョン 1.5.0。冷蔵庫・レシピが普段どおり。
2. 材料の一部が足りず、代替できる食材(例: キャベツの代わりの白菜)があるレシピが「代替で作れます」になる。
3. レシピ詳細で「代わりに 白菜 0.6玉」が出る。「これを作る」で代替の行を確かめて確定すると、白菜の在庫が減る。
4. 「最近作った記録」の「取り消す」で在庫が戻る。
5. 「この代替を使わない」でその代替が消え、グループ画面の「使わないことにした代替」から戻せる。

アプリは v1.4.0 に Instant Rollback。014 のテーブルは残っても v1.4.0 の動作に影響しない(v1.4.0 は旧 cook_recipe を使う)。
